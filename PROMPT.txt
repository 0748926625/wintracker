PROMPT CLAUDE CODE — WINTRACKER MVP

Je veux développer rapidement une application Web Progressive Web App (PWA) appelée WINTRACKER.

WINTRACKER est une plateforme de gestion et de suivi des colis exploitée par WINNER EXPRESS.

WINNER EXPRESS est une structure de livraison qui travaille principalement avec des compagnies de transport interurbain.

==================================================
1. OBJECTIF DU MVP
==================================================

Je veux construire le minimum vital permettant à WINNER EXPRESS de gérer ses livraisons et permettant aux compagnies de transport partenaires de suivre leurs colis en temps réel.

Le scénario principal est :

COMPAGNIE DE TRANSPORT
        ↓
remet le colis à WINNER EXPRESS
        ↓
WINNER EXPRESS affecte le colis à un livreur
        ↓
LIVREUR récupère le colis
        ↓
LIVREUR effectue la livraison
        ↓
DESTINATAIRE reçoit le colis
        ↓
COMPAGNIE voit immédiatement le nouveau statut

Le MVP doit permettre :

1. WINNER EXPRESS de gérer les compagnies partenaires.
2. WINNER EXPRESS de gérer les livreurs.
3. WINNER EXPRESS de créer les colis.
4. WINNER EXPRESS d'affecter les colis aux livreurs.
5. Les livreurs de consulter leurs colis.
6. Les livreurs de modifier le statut des colis.
7. Les livreurs de confirmer une livraison.
8. Les livreurs de déclarer un échec.
9. Les compagnies partenaires de consulter leurs colis.
10. Les compagnies de voir les changements de statut EN TEMPS RÉEL.
11. Conserver l'historique des changements de statut.

Ne pas développer de fonctionnalités secondaires pour le moment.

==================================================
3. ARCHITECTURE MULTI-TENANT
==================================================

WINTRACKER doit être conçu dès le départ comme une application multi-tenant.

Chaque compagnie de transport partenaire constitue un tenant.

Exemple :

WINNER EXPRESS
│
├── Compagnie A
│   ├── utilisateurs
│   └── colis
│
├── Compagnie B
│   ├── utilisateurs
│   └── colis
│
└── Compagnie C
    ├── utilisateurs
    └── colis

REGLE ABSOLUE :

Une compagnie ne doit jamais pouvoir consulter les colis d'une autre compagnie.

Cette sécurité doit être appliquée au niveau PostgreSQL/Supabase avec RLS.

Ne jamais compter uniquement sur le frontend pour sécuriser les données.

LIVREUR
↓

↓
Realtime
↓
ESPACE COMPAGNIE

Exemple :

Le statut devient :

LIVRE

🟢 LIVRÉ

sans recharger la page.

Implémenter correctement :

- subscription ;
- mise à jour de l'interface ;
- reconnexion ;
- unsubscribe lorsque le composant est démonté.

32. RÈGLE PRINCIPALE
==================================================

JE VEUX LE MVP LE PLUS SIMPLE ET LE PLUS RAPIDE POSSIBLE.

Ne cherche pas à construire toute la plateforme logistique dès maintenant.

Le cœur du produit est :

"PERMETTRE À WINNER EXPRESS DE GÉRER UN COLIS ET À LA COMPAGNIE QUI L'A ENVOYÉ DE SAVOIR EN TEMPS RÉEL OÙ EN EST CE COLIS."

Toute fonctionnalité qui ne sert pas directement ce scénario doit être reportée.

Avant de coder :

1. analyse rapidement l'architecture ;
2. présente le schéma des tables ;
3. présente les rôles ;
4. présente les RLS ;
5. présente le workflow des statuts.

Puis commence immédiatement l'implémentation.

Ne demande pas de confirmation pour chaque petite décision technique.

Prends les décisions raisonnables toi-même.

À chaque étape :
- code ;
- vérifie les erreurs ;
- corrige ;
- teste ;
- puis continue.

L'objectif est d'obtenir le plus rapidement possible une première version réellement fonctionnelle de WINTRACKER.
